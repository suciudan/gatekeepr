# Missing Check Expansion Plan for Gatekeepr

## Summary
- Current coverage is solid on local email heuristics, disposable domains, domain syntax/MX/age, cloud/Tor/blocklist IPs, and basic scraper UA detection.
- The biggest missing check families are: normalization and provider intelligence, mailbox-level enrichment, customer-owned policy checks, and behavioral/history checks.
- Reference market surface: UserCheck publicly exposes signals like `public_domain`, `relay_domain`, `did_you_mean`, and `blocklisted` in its API docs, while Hunter documents SMTP and `accept_all` style mailbox checks, and Abstract documents typo-correction flows. Sources: https://www.usercheck.com/docs/api/response , https://hunter.io/api-documentation/v2#email-verifier , https://www.abstractapi.com/guides/email-validation/correct-email-typos

## Key Changes
- Phase 1, cheap synchronous checks that help both signup scoring and CSV screening:
  - Add `email_public_provider` and `email_relay_domain` checks to separate normal public inboxes from privacy-forwarding services.
  - Add `email_typo_domain` with `did_you_mean` suggestions for domains like `gmal.com`, `hotnail.com`, or similar near-miss providers.
  - Add canonicalization checks for provider-specific aliases such as Gmail dots/plus addressing and emit `info.email_canonical` for dedupe and policy matching.
  - Add `domain_null_mx` and stronger mail-capability checks so domains that explicitly do not accept mail are flagged separately from generic MX errors.
  - Add Unicode/punycode homograph checks on the domain side to catch visually deceptive domains.

- Phase 2, customer-owned policy checks:
  - Add workspace-scoped `email_customer_blocklisted`, `domain_customer_blocklisted`, `email_customer_allowlisted`, and `email_suppressed`.
  - Apply policy checks to both real-time API requests and bulk CSV jobs using canonicalized email/domain values.
  - Make allow, block, and suppress lists first-class inputs to scoring and export segmentation.

- Phase 3, async mailbox enrichment:
  - Add optional mailbox-level checks for `mailbox_smtp_reachable` and `email_accept_all`.
  - Keep these out of the default real-time path; expose them through async enrichment and bulk CSV processing first.
  - Make mailbox verification optional in self-hosted deployments.

- Phase 4, behavioral checks:
  - Add tenant-scoped velocity checks such as `ip_signup_velocity_high`, `domain_signup_velocity_high`, and `email_local_pattern_reuse`.
  - Add repeated-abuse checks based on recent history: same IP hitting many local parts, same domain reused across many signups, or repeated risky prefixes within a short window.
  - Add CSV-specific concentration checks such as “too many rows from one risky domain family” or “high duplicate/canonical collision rate.”

## Public Interfaces
- Keep current endpoints stable.
- Extend result payloads with:
  - `threats`: new policy, relay, typo, null-MX, accept-all, and velocity signals.
  - `trust`: `email_public_provider`, `email_customer_allowlisted`, and similar low-risk indicators.
  - `info`: `email_canonical`, `email_suggested`, `mailbox_enrichment_status`, policy matches, and recent velocity counters.
- Add async enrichment semantics for heavy checks instead of slowing the default API path.

## Test Plan
- Typo and normalization: common provider typos, Gmail alias normalization, plus-address variants, Unicode/punycode spoof cases.
- Provider and relay: Gmail/Outlook/Yahoo as public providers, iCloud/Firefox/SimpleLogin-style relays as relay domains, disposable domains still taking precedence as threats.
- Policy: allowlist, blocklist, and suppress list matches on exact and canonicalized values; workspace isolation between tenants.
- Mailbox enrichment: reachable mailbox, unreachable mailbox, accept-all domain, transient SMTP failure, and optional self-host disablement.
- Behavioral: short-window IP/domain bursts, repeated local-part patterns, CSV duplicate concentration, retention-window expiry, and tenant-scoped counters.

## Assumptions
- The next check expansion should improve both real-time signup scoring and CSV risk hygiene.
- Cheap signals and mailbox-level signals are both in scope, but mailbox verification runs asynchronously.
- Customer-owned allow, block, and suppress lists are part of the next check set.
- Behavioral checks are enabled with configurable retention and start tenant-scoped before any global reputation layer.
