# Business-Value Feature Plan for Gatekeepr

## Summary
- Build Gatekeepr as one product with two modes:
  - Developer mode: real-time API for signup and abuse prevention.
  - Operations mode: non-technical bulk CSV screening for marketing, RevOps, and other business teams.
- The first revenue-driving feature bundle should be bulk CSV screening with segmented export.
- Position the CSV product as `risk hygiene`, not guaranteed deliverability: Gatekeepr screens suspicious, disposable, role-based, and low-trust emails before outreach or activation.
- Support indie SaaS, agencies, and enterprises through packaging and permissions, not by building three separate products.

## Key Changes
- Bulk CSV screening:
  - Add an upload flow for CSV files with email-column selection, async processing, job status, and downloadable results.
  - Preserve all original columns and append Gatekeepr fields such as `fraud_score`, `threats`, `trust`, `recommended_action`, and `reason_summary`.
  - Export segmented files by outcome: `allow`, `review`, `suppress`.
  - Cap list size by plan and queue jobs for larger accounts.

- Product packaging:
  - Indie SaaS: self-serve API, simple thresholds, usage dashboard, CSV upload for one-off cleaning.
  - Agencies: multi-workspace or multi-client views, shared billing, per-client API keys, client-scoped CSV jobs.
  - Enterprise: SSO/RBAC, audit logs, private datasets, dedicated support, custom policies, and higher-volume async processing.
  - Keep one underlying risk engine and expose segment-specific controls through plans and permissions.

- Stickier business features:
  - Add policy presets for common jobs: signup protection, free-trial abuse, outbound prospecting, newsletter hygiene, marketplace review.
  - Add saved suppression lists and reusable blocklists so results compound over time.
  - Add webhook or email notifications when jobs finish and when API usage or risk spikes cross thresholds.
  - Add job history, result retention settings, and downloadable reports for internal sharing.

- Messaging and monetization:
  - Sell the CSV workflow as "screen your list before you spend campaign budget."
  - Sell the API as "stop risky users before they consume credits or support time."
  - Introduce clear self-serve tiers with separate limits for real-time API requests and bulk-screened rows.
  - Keep manual enterprise sales only for SSO, custom policy logic, SLA, or private deployment.

## Public Interfaces
- Keep existing API endpoints stable for real-time customers.
- Add a bulk job interface with these minimum capabilities:
  - CSV upload with selected email column.
  - Async job status and completion result retrieval.
  - Row-level appended result fields plus segmented export.
- Add `recommended_action` semantics consistently across API and CSV results: `allow`, `review`, `suppress`.

## Test Plan
- CSV ingestion:
  - valid CSV, missing email column, malformed rows, duplicate emails, large files, UTF-8 edge cases.
- Risk outputs:
  - disposable domains, role accounts, malformed emails, known free providers, suspicious composition, mixed clean/risky lists.
- Export behavior:
  - original columns preserved, appended columns correct, segmented files consistent with per-row action.
- Multi-segment product behavior:
  - plan-based limits enforced, workspace isolation holds, client-specific data is separated, enterprise-only features remain gated.
- Commercial validation:
  - users can understand the value of bulk screening without docs, complete a job end-to-end, and download a usable suppression/review list.

## Assumptions
- Gatekeepr remains one product with two modes rather than splitting into separate brands.
- Bulk CSV screening is the first feature bundle to prioritize.
- The CSV promise is `risk hygiene`, not hard deliverability or mailbox-existence guarantees.
- Output should be export-first, with preserved source columns and segmented downloadable files.
- All three customer segments matter, but they will be served through tiered packaging on one common platform rather than parallel bespoke workflows.
