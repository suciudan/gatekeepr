# Gatekeepr Platform Modernization: TypeScript, Docker Compose, and Self-Hosting

## Summary
- Migrate the monorepo to a full TypeScript codebase first, then containerize the supported self-host stack and replace the current manual VPS docs with one Compose-first guide.
- The official self-host bundle on day one will be: `api + mysql + redis + crons + dash`.
- The self-host stack will use bundled Caddy for HTTPS/reverse proxy, one dedicated cron container for scheduled jobs, and local admin credentials for `dash`.
- `site` and `apps/docs` stay in the repo and should be migrated to TypeScript where applicable, but they are not part of the first supported self-host deployment.

## Key Changes
- TypeScript full cutover:
  - Add a root TypeScript toolchain and workspace `tsconfig` hierarchy, then convert all code-bearing workspaces from `.js/.jsx/.mjs` to `.ts/.tsx` while keeping ESM.
  - Convert shared packages first (`config`, `core`, `db`), then `api` and `crons`, then `dash`, `site`, and `debugger`, then tests and build/config files.
  - Introduce shared types for request context, fraud results, check definitions, env/config, usage stats, and cron job payloads.
  - Add repo-wide `typecheck` scripts and Turbo tasks; TypeScript build/typecheck becomes required before container work starts.

- Docker Compose self-host stack:
  - Ship a root Compose deployment with services: `api`, `dash`, `crons`, `mysql`, `redis`, and `caddy`.
  - Use official images for `mysql`, `redis`, and `caddy`; build custom images for `api`, `dash`, and `crons`.
  - Persist volumes for MySQL, Redis, and Caddy state; expose only Caddy on `80/443`, keep app services internal on the Compose network.
  - Run scheduled refresh/reset jobs inside a dedicated `crons` container using an internal scheduler and a checked-in cron definition matching the current job cadence.

- Self-host auth and configuration:
  - Replace the current Google-only dashboard auth path for self-host with local admin credentials.
  - Use a simple bootstrap admin model via env-backed credentials for v1 self-host; no Google OAuth required in the supported self-host flow.
  - Standardize one canonical self-host env contract with checked-in examples for every supported service.
  - Make Compose the primary deployment path and demote the current Nginx/systemd/manual-host docs to legacy reference only.

- Documentation:
  - Rewrite the root README around quick start, architecture, supported services, and self-host scope.
  - Add a dedicated self-host section in `apps/docs` covering prerequisites, DNS, HTTPS, env setup, first admin login, API key management, upgrades, backups, restore, and cron/data freshness expectations.
  - Document what is intentionally out of scope for the first self-host release: public marketing site, docs hosting, enterprise SSO, and multi-node scaling.

## Public Interfaces and Types
- API routes remain stable; the main interface changes are internal typing and deployment/runtime interfaces.
- Add typed contracts for:
  - API request/response context and fraud result shapes.
  - Check registration and execution signatures.
  - Usage/stat objects shared between `api`, `dash`, and `core`.
  - Self-host env variables and Compose service configuration.
- Add a documented local-admin auth interface for self-host `dash`, driven by bootstrap credentials rather than Google OAuth.

## Test Plan
- TypeScript migration:
  - `typecheck` passes across all workspaces.
  - Existing tests run after conversion, with no regression in API behavior.
  - Next.js apps build cleanly after `.tsx` migration and path alias updates.
- Container stack:
  - One-command Compose startup brings up `api`, `dash`, `crons`, `mysql`, `redis`, and `caddy`.
  - Fresh self-host install supports first admin login, dashboard access, API-key management, and API requests through Caddy.
  - Cron jobs execute on schedule inside the containerized stack and update Redis/MySQL-backed state as expected.
- Docs:
  - A clean machine can follow the single-server guide end-to-end without using the legacy VPS docs.
  - Backup/restore and upgrade steps are tested against the Compose deployment.

## Assumptions
- TypeScript is a full cutover, not an incremental mixed JS/TS migration.
- The work is staged as `TypeScript first`, then `Docker Compose + self-host docs`.
- The official day-one self-host stack includes `api + mysql + redis + crons + dash` and excludes `site` and public docs hosting.
- Compose replaces the old manual deployment path as the primary documented installation method.
- Self-host `dash` uses local bootstrap admin credentials in v1; enterprise SSO is deferred.
